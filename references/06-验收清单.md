# 设计与工程验收清单（逐项检查）

## 数据与叙事
- [ ] 每幅图有业务问题、标题、数值单位、时间口径、来源或“模拟数据”标识。
- [ ] 不将相关性说成因果，不将增长额与增长率混用，负数与百分比处理正确。
- [ ] 图表强调与文本结论一致，结论可从数据直接验证。
- [ ] 核心路径形成“总览 → 异动 → 解释 → 明细 → 行动”。

## 视觉
- [ ] 统一 token：字体、字号、边距、间距、色彩、圆角、线宽与网格。
- [ ] 图表有稳定的 y 轴基线/清晰的尺度说明；不能用截断柱形误导。
- [ ] 图表关键标注可见，坐标与网格克制；中文字符不拥挤、不截断。
- [ ] 所有小倍数/比较图轴口径一致，误差条/样本数有说明。

## 交互
- [ ] 全局筛选与表格及 KPI 同步，状态有可见的已选提示和重置。
- [ ] 空数据、加载、错误与无权限分别处理。
- [ ] 滚动章节切换可预测；不会在用户主动筛选后突然覆盖已选值。
- [ ] 键盘可使用筛选；焦点态可见；图表有替代文本和明细表。

## 响应式与性能
- [ ] 360/768/1440px 检查中文排版、标签与交互点击范围。
- [ ] `prefers-reduced-motion` 时仍可读。
- [ ] 图形高密度时选择 Canvas/WebGL 或聚合；超大数据服务端汇总。
- [ ] 严格区分已测试事项与尚未测试的事项，不虚构性能数字。

## 模板扩展
- [ ] registry 的 ID/slug/别名唯一，新增模板不覆盖旧模板。
- [ ] 记录来源、evidence_status 与设计主张；不确定处标记待核验。
- [ ] 新增模板有 STYLE.md、template.json，并通过脚本验证。
