# 07｜专业图表选择与视觉编码（v1.1）

本规范为可复用专业图表系统，不声称这些图形都存在于 Google AI Studio 原模板。**权威机器可读目录：`charts/catalog.json`**。

## 按任务检索

### A. 趋势与异常
- `annotated-line`：时间趋势 + 事件标注。**业务例**：同期销售指数。
- `small-multiples`：同轴或明确独立轴的小倍数趋势。**业务例**：省份横向比较。
- `bump-chart`：排名的时间轨迹。注意*名次不是体量*。
- `calendar-heatmap`：时间日历上定位异常日期，缺失和 0 要区分。
- `control-chart`：中心线、统计上下控制限与异常点；业务目标线不能冒充控制限。

### B. 精准对比与目标
- `dumbbell`：同对象两个时点的变化量；同单位、同样本。
- `slopegraph`：两个时点的变动方向与对照。
- `bullet`：实际值、目标值和业务绩效区间；是信息密度高的紧凑指标图。
- `diverging-bars`：以 0 为基线的正负变化（允许回落/提升同时出现）。
- `lollipop`：比较少量对象排序。
- `pareto`：贡献条 + 累计占比（两条尺度要写清）。

### C. 结构、归因与流向
- `waterfall`：一个合计量增减的桥接分解；分解项必须相加能回到目标。
- `sankey`：流量从来源到去向；每个环节的损耗要保持守恒或标出“其他/损耗”。
- `funnel`：**同一 cohort** 经过不同阶段的转化，不能混不同人群。
- `chord`：多个节点的双向关联，但密度大时矩阵更清楚。
- `treemap`：层级+面积的构成；适合正数总量。
- `marimekko`：比较不同区域的**体量 + 结构占比**。
- `waffle`：解释占比的视觉辅助，不用于细小差距的精密对比。

### D. 分布与关系
- `scatter-quadrant`：双指标关系+阈值分层；不要宣称因果。
- `hexbin`：百万级门店点在浏览器端渲染前应先聚合，以密度编码分布。
- `boxplot`：中位数、Q1、Q3 和须线。必须声明须线规则与样本量。
- `violin` / `ridge`：估计密度。小样本或带宽不合理时易产生假象。
- `uncertainty-band`：预测结果区间须写明是置信区间还是预测区间。

### E. 零售 / 供应链
- `cohort-heatmap`：按加入/试卖/开店批次比较第 N 月保留率；未来月份必须显示 N/A。
- `inventory-heatmap`：商品×仓的风险矩阵，缺失值不能用 0。
- `seasonal-matrix`：月份季节性，需标准化营业日/门店数。
- `supply-otif`：及时与足量双维，真正 OTIF 必须根据同一订单同时满足条件统计。
- `flow-network`：供应商、仓、门店关键链路，标明边权含义。
- `geo-density`：门店与物流空间密度，注意投影与敏感地理信息处理。

## 输出图形必须包含的“九件套”
1. 为什么用这张图：业务问题。
2. 适用的数据粒度与单位。
3. 基础值、分母或基期定义。
4. 编码映射（位置/长度/面积/颜色/线型）。
5. 统计转换、聚合与缺失规则。
6. 图上直接标注与基准线。
7. 可交互点及筛选/钻取行为。
8. 数据表与无障碍替代文本。
9. 误用/性能风险及渲染器选择。

## 模板与组件层如何组合
- **编辑式 T001**：图表内直接叙述，重点系列强调，非核心辅助元素低对比；图表与正文共用栅格。
- **图表语义层**：同一 waterfall 可以适配多个视觉模板，但守恒、顺序、基线的要求不变。
- **扩展模板**：新增 `T002` 不应该复制整个图表库，只定义 token 和对图表的外观映射。
