# 基础设计原则 · Editorial Data Experience

## 设计目标
以“观点清楚、图形可靠、信息可查、操作可控”为优先级。网页不是堆 KPI 卡片，而是引导读者从一个问题走到一个证据支持的决策。

### 五条核心原则
1. **故事优先**：每屏回答一个业务问题；图表要有结论性标题，不仅有“销售趋势”。
2. **可视化即排版**：图形、正文、注释在同一网格，文字是图形的一部分，而不是后期覆盖。
3. **用设计标记证据**：强调色用于重点系列、变化与状态；红/绿需配合箭头、文本或形状，并遵守业务语义。
4. **安静的视觉层级**：主标题、关键数值、图形证据最高优先；次级坐标线、边框和装饰逐级降低对比。
5. **可核验与可操作**：每幅图提供时间口径、单位、来源和可追溯的数据表；交互状态可撤销/重置。

## 推荐层级（不是原始网站的验证结果）
- 页面宽度：1280px 以内内容容器，分析页 `max-width: 1440px`；正文阅读列宽 50–75 中文字符；布局优先按内容流动。
- 网格：12 栏桌面、6 栏平板、单列手机；间距基线 8px。
- 字体：中文无衬线用系统字体（思源黑体/苹方/微软雅黑等）；英文数字可使用 ui-monospace；要做杂志感可为少量英文大标题搭配衬线体。
- 字阶建议：封面/专题 40–64px；二级章节 26–34px；正文 15–17px；注释 12–13px，确保对比度。
- 图表：直接标注优先于远距离图例；标题说明发现，图注解释口径；给宽裕留白；移动端不强压小字。

## 默认结构
`01 背景/问题 → 02 核心变化 → 03 差异来源 → 04 证据/钻取 → 05 行动建议`

## 视觉 token 职责
- `canvas / surface / ink / muted / grid`：空间、层级与阅读舒适度。
- `accent / accentSoft`：聚焦、选择、重点系列；非警报。
- `positive / negative / warning`：在业务有明确语义时才使用；不要让颜色独立表达涨跌好坏。
- `radius / space / shadow`：一致的容器语言，避免装饰压过数据。

## 反模式
装饰性立体柱、反复渐变、不解释颜色的多色图、每张图都用同一个饼图、所有图都需要 hover 才能看数值、没有单位、黑箱“异常归因”结论、仅桌面可见的交互。
