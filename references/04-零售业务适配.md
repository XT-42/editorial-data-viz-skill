# 零售、采购、供应链场景映射

本文件面向商品—仓—店经营分析；所有示例是建模建议，不是假设用户一定拥有这些字段。

## 5 章故事板
1. **经营概况**：销售额、销量、毛利、门店覆盖、库存周转；与目标/同期的差异。
2. **增长归因**：品类/商品/区域贡献，以可解释的分解方法观察，而不是自动声称因果。
3. **供应链执行**：要货、采购、到货、OTIF、出库、缺货，按订单和商品仓口径区分。
4. **门店差异**：同店、在营、新店、分省/城市、分生命周期；明确样本筛选。
5. **行动建议**：阈值异常的对象清单、潜在损失测算口径、优先级和负责人。

## 典型图表映射
| 分析页 | 图形优先级 | 筛选维度 | 风险 |
|---|---|---|---|
| 同店同比 | 同店趋势 + 分布 + 门店明细 | 时段、省、门店群 | 同店定义必须固定去年及今年同期都存在销售的店集；还要处理关闭/开店 |
| 商品销售贡献 | Pareto 条形 + 贡献瀑布 + 散点 | 品类/品牌/SKU | 贡献额、贡献率、同比增速是不同量 |
| 采购与要货 | 达成曲线 + 计划差异 + 订单表 | 商品仓、采购方、日 | 订单与实收时间粒度不同 |
| 缺货与库存 | 时间热力 + 7 日趋势 + 异常清单 | 仓/店/SKU | 有效库存、在途、不可售不得混加 |
| 门店网络 | 地图分布 + 密度网格 + 区域比较 | 门店类型、区域、时段 | 地图点多时使用聚合/瓦片/地理索引 |

## StarRocks → 网页的推荐链路
1. 先在 StarRocks/服务端完成口径统一、分区裁剪、聚合、TopN、采样与分页。
2. API 明确返回 `grain`、`unit`、`date_range`、`filters_applied`、`updated_at`。
3. 趋势图按合理时间粒度返回聚合数组；明细表支持 server-side 排序和分页。
4. 图表状态与 URL 参数同步，避免滚动叙事覆盖手动筛选。
5. 响应慢时展示最近更新时间与加载进度，不能伪造实时性。
