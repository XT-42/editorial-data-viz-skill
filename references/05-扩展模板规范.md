# 模板扩展协议 v1

## 设计意图
核心 Skill 流程稳定，新增设计风格只能通过新的 `templates/<slug>/` 子目录扩展，禁止改写其他模板文件。`templates/registry.json` 是唯一权威的模板索引。

## 最小格式
```
templates/
  registry.json
  _template-blueprint/           # 未注册起始模板
  google-ai-studio-interactive-dashboard/
    template.json
    STYLE.md
  future-template-name/
    template.json
    STYLE.md
```

- `registry.json`：`version`、`default_template_id`、`templates[]`、`reserved_slots[]`。
- 模板索引项：`id`、`slug`、`name`、`aliases`、`status`、`evidence_status`、`path`、`source_url`。
- 模板 `template.json`：同一 `id`、`slug`，加 `design_pillars`、`tokens`、`chart_patterns`、`interaction_patterns`、`responsive_rules`、`implementation` 等。
- `STYLE.md`：人类可读，包含来源/验证情况、视觉提炼、排版、色彩、图形与状态、与其他模板区别、待核验项。

## 可验证的证据状态
- `derived-from-conversation`：仅根据对话中总结的方向制定；不能声称原网页使用具体字体、颜色或图表。
- `reviewed-screenshot`：确有画面/截图；注明观察范围。
- `reviewed-source`：检查过用户允许访问的源码；注明版本、模块与许可。
- `user-specified`：用户直接给出了视觉要求；应标为“用户规范”而非“网站实测”。

## 自动添加
```bash
python scripts/add_template.py --slug new-editorial --name '新设计方案'   --source 'https://example.com' --description '一句话区别' 
python scripts/validate_skill.py
```
- 优先使用 `reserved_slots` 第一个槽位（如 T002），完成后补充未来槽位；注册表不重复 ID、slug 和 alias。
- 新增状态先是 `draft`；准备好的模板经人工核验后可以将 `status` 改为 `active`。
- 缺失图片、访问失败、只有 URL：仍可登记为 draft，证据状态不能升级成“已验证”。

## 多模板组合优先级
1. 用户当次显式要求与真实数据语义优先。
2. 共通质量规则（准确、可访问、移动端）永远生效。
3. 选择一个模板作“排版与色彩主视觉”，其他模板只借用局部图表/动效技巧。
4. 冲突时记录 `主模板 + 借鉴模板 + 采用元素 + 放弃元素 + 原因`。
5. 新增模板与原模板的区别必须可解释，不能只是换色。
